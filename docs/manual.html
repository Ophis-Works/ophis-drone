User manual. Sources: PLAN.md (binding design), IMPLEMENTATION.md, src/config.h, src/ui/ui.c, src/dsp/, src/preset/schema.c, Makefile, BUILD_NOTES.md, CHECKLIST_R36S.md.

1. What it is

ophis-drone is a three-chain drone synthesizer for Linux, written in C11 against SDL2 (video) and ALSA (audio). It runs as a desktop application and as a native build for the R36S handheld (Rockchip RK3326, ArkOS). The UI is a single fixed 640×480 logical screen (SDL2, desktop window 1280×960 at scale 2, handheld fullscreen at scale 1) rendered with a built-in bitmap font — no external assets.

Each of the three chains (A, B, C) has one main oscillator, two sub-oscillators that modulate the main one, an ADSR envelope, a mode-selectable filter (LP/HP/BP/BR) and level/velocity. Chains B and C sum into the master bus and can simultaneously modulate any chain (A, B or C) via a cross-mod matrix whose slots carry a routing TARGET; each chain also has its own MIX VOLUME master send (MASTER page). After the mixer, the signal passes through a stereo delay and a reverb, then a master safety filter, master level and master gate. Three sequencers (one per chain, togglable) send frequency (Hz) and velocity steps to their chains. All parameters except the RUN transport flag are saved and loaded as JSON preset files.

There are no musical notes or scales anywhere: every pitch parameter is a frequency in Hz (0.1 Hz–20 kHz).

Architecture: one process, two threads (host/engine/audio and UI), communicating only through lock-free channels — a double-buffered parameter mailbox, atomic event flags (TRIGGER/PANIC; RUN travels in the mailbox) and an atomic-pointer status snapshot. Audio: 44100 Hz, float32, stereo, 256-frame periods. The desktop gate requires a measured ALSA xrun count of exactly 0.

2. Features

2.1 Tabs

Five top tabs (Q/E on desktop, L/R shoulder on R36S; wraps): OSC 1 | OSC 2 | OSC 3 | MOD | MASTER. Each OSC tab has three sub-tabs: OSC | ENV+FLT | SEQ. MOD and MASTER have no sub-tab row. Arrows start on the sub-tab row (LEFT/RIGHT cycles sub-tabs, DOWN enters content, UP returns to the row); inside content UP/DOWN move the cursor (wrap), Z/X (desktop) / X/Y (R36S) edit (slider ±1 step, label cycles one option); LEFT/RIGHT is navigation only (sub-tab row; on SEQ pages it selects/moves the step rectangle from anywhere in content, elsewhere in content it is inert). Cursor/focus persist per tab+sub-tab.

Every page except SEQ is split into labeled sections: a gray non-selectable section label row at the left margin, the section's items indented (two spaces) below it, and ONE empty 16 px row between a section's last item and the next section label (none after the last section). Labels and gaps are visual only — the cursor walks the page's flat item list (0..N−1, wrap) and skips over them visually.

2.2 Parameters and ranges

OSC tab — OSC sub-tab (per chain)

Sections: MAIN (5 items), then SUB 1 and SUB 2 (4 items each; identical sets) — 13 items in one flat list. The ADSR controls are NOT on this page (they live in the ENV+FLT sub-tab's ADSR section).

ItemRange / options
FREQ0.1 Hz – 20 kHz, log, 1/12-octave steps (0.1 × 2pos/12, pos 0..212); dimmed/inert for noise waves
WAVEsine · tri · saw · square · white · pink (all normalized −1..1); saw and square are band-limited (edge smoothing at twice the sample rate — no alias harshness)

LEVEL0–100 %, 1 pp steps
VEL0–100 % — retrigger level used by TRIGGER and by direct mode when RUN is ON

OSC tab — SUB 1 / SUB 2 sections (identical sets)

The two SUB sections of the OSC sub-tab (formerly their own SUB sub-tab), each with:

ItemRange / options
DIVsubharmonic divider 1..16 — the sub plays parent_f / div (Subharmonicon-style integer division; 1 = unison, 2 = one octave down, …)
WAVEsine · tri · saw · square (subs are tonal voices — no noise; saw/square band-limited like the main osc)
DUTYsquare pulse width 5–95 %, dimmed unless WAVE = square
LEVEL0–100 % — the sub's audio mixed into the chain's OSC sum (0 = inaudible); level never changes what the MOD matrix taps

Subs are Spice/Subharmonicon-style AUDIO voices (PLAN_OPTIMIZATION.md O2): they sum into the oscillator output BEFORE the envelope and filter and carry no destination knobs — a sub modulates through the MOD matrix (SRC = B.SUB1 etc.), which is unaffected by its LEVEL.

Sections: ADSR (4 items) then FILTER (5 items) — 9 items in one flat list. The envelope controls live here (the OSC page's MAIN section has none).

ATTACK / DECAY / RELEASE0–60 s, log/exp: pos 0 = 0 s; pos 1..50 = 0.001 s × 60000(pos−1)/49
SUSTAIN0–100 %

MODELP · HP · BP · BR (RBJ biquad)

OSC tab — SEQ sub-tab (per chain, step page)

Single column, one parameter per row (cursor order = visual order): SEQ ON (ON/OFF — a UI parameter, never a button), DIV (clock divider, integer 1–16, shown /1../16, default 1; step period = 60/BPM/4 × div seconds), MODE, ONCE. Then — after two blank lines under a gray “Steps” label — the row of eight step rectangles (LEFT/RIGHT — desktop arrows / R36S d-pad — selects/moves the rectangle from anywhere on the SEQ page; the selected step — the one PITCH/VEL edit — has a thicker border; the step playing now is marked by an orange dot inside the square; cells are filled when vel > 0, empty when vel = 0; value edits are Z/X (desktop) / X/Y (R36S)). Then PITCH (0.1 Hz – 20 kHz, log 1/12-oct) and VEL (0–100 %) sliders bound to the selected rectangle; editing changes that step live. BPM is not here: the tempo is one global integer 1–500 for the whole synth, visible and edited on the MASTER tab. There is no per-step active flag — vel 0 is a silent step (no event, the drone sustains). Sequencers run only while RUN is ON.

SEQ modes (5) and ONCE

  • fwd (default): steps 1→8, repeats.
  • pingpong: 1→8 then 8→1, bouncing.
  • oddeven: 1,3,5,7 then 2,4,6,8.
  • random: deterministic per-instance PRNG, never repeating the same step immediately.
  • markov: equally weighted 1-D random walk (±1 at p = 0.5), reflecting at the edges.

ONCE: loop (default) repeats the mode's order forever; once plays one pass through the order, then stays silent until restarted (RUN off→on, sequencer off→on, or PANIC reset; for random/markov a pass is a fixed count of 8 steps).

MOD tab

One section, MOD. The SLOT row selects the matrix slot (1–16; LEFT/RIGHT from any row on the page, or X/Z on the SLOT row, rolling over); the rows below edit the selected slot: SOURCE (OFF · B.OSC · B.SUB1 · B.SUB2 · C.OSC · C.SUB1 · C.SUB2 · A.OSC · A.SUB1 · A.SUB2 — any chain's raw osc/sub output; self-routing is legal), TARGET (A · B · C — which chain the slot's modulation and ADD feed; default A), DEST (OFF · PITCH · PHASE · AMP · FLT CUT · FLT RES · FLT ENV · RING · FM · ADSR A · ADSR D · ADSR S · ADSR R; A/D/R scale their stage time ±100 %, S shifts ±100 points), DEPTH (same ranges/rules as sub AMT; the knob reads +50 Hz under PITCH, 100 % under RING, +4 IDX under FM) and LEVEL (the slot's ADD knob — the source's audio blended into the TARGET, 0–100 % wet, independent of DEST; a slot can add AND modulate, or either alone). Cross-chain sources are read one sample late. The modulation is applied at the TARGET's oscillator stage — before the target's own ADSR and filter. Mixer output: tanh(1.5 × Σ (mixvol[c]/100 × out[c])).

MASTER tab

Sections: MASTER — MASTER level (0–100 %), SAFETY (boolean, default ON) and BPM — the one global tempo (integer 1–500) shared by all three sequencers, visible and edited here, never on the SEQ pages — then DELAY and REVERB, the master-path delay and reverb controls (the former dedicated FX page, removed in the tab reorg). The master path runs, in fixed order: chains (each scaled by its MIX VOLUME) → mixer (sum + tanh + cross-mod) → delay → reverb → safety filter → master level → master gate. MIX VOLUME (0–100 %, default 100) is the chain's master send: it scales the chain's post-ADSR/FILTER signal into the master sum and NEVER touches modulation — a chain with MIX 0 is silent at master but still drives mod slots as a source. Safety ON = 4th-order rolloff via cascaded biquads (HP 60 Hz + LP 18 kHz); OFF = bypass. The master gate (10 ms ramp) is applied after master level, per sample. Items (flat cursor order):

ItemRange
MIX A / MIX B / MIX Cper-chain master send, 0–100 % (default 100)
DELAY TIME L0–2 s, 0.01 s steps (stereo lines of 2 s; TIME R is a preset field)
DELAY FEEDBACK0–100 %
DELAY TONELP cutoff in the feedback loop, 20 Hz – 20 kHz, log 1/12-octave
DELAY MIX0–100 % (0 = dry passthrough)
REVERB SIZE0–100 % (FDN/Schroeder class)
REVERB DAMP0–100 % (damping LP inside the loop)
REVERB MIX0–100 %
REVERB WIDTH0–100 % (mid/side spread)

Factory defaults make both FX silent (all wet values 0).

2.3 Transport

RUN toggles the transport: ON opens the gate (10 ms ramp) and runs the sequencers (or direct mode — one retrigger at the chain's VEL on the oscillator's parametrized frequency, for chains whose sequencer is OFF); OFF closes the gate, stops the sequencers and releases all chains. TRIGGER fires all three chains once at their VEL, overrides RUN OFF by holding the gate open until all envelopes reach zero (30 s safety timeout), and never touches the sequencers. PANIC (menu item, immediate, no ramp): RUN cleared, gate 0 instantly, all envelopes idle, all oscillator phases and biquads and sequencer clocks and FX state reset. Exit is menu-only — there is no quit key.

2.4 Menu

Opened by Start (R36S) / Esc (desktop) on any screen; overlay. Items: NEW (confirm prompt — reset to factory defaults), SAVE (name entry), LOAD (folder navigator), PANIC (immediate), EXIT (quits after a 1 s flash), BACK. Inside the menu and its sub-windows the CONFIRM key selects (Enter on desktop, A on R36S) and Esc cancels/closes — on desktop Esc is the only cancel (Space and T do nothing inside menus); Q/E are inactive. Preset names: 1–32 characters from A–Z, a–z, 0–9, space, _, -. Desktop SAVE: type on the keyboard, Enter saves, Esc cancels. R36S SAVE: character grid — d-pad selects a cell, X inserts, Y deletes, A saves, B cancels. LOAD lists subdirectories (suffix /, .. to go up) and *.json presets alphabetically and can navigate any readable folder. The default presets folder is created on first LOAD; a folder that cannot be opened falls back to its parent, like any file picker.

2.5 Preset files (JSON version 2)

One JSON file per preset, stored in presets/ next to the executable (resolved at runtime from /proc/self/exe). A preset serializes everything in synth_params_t except the run flag. Written and parsed by the schema layer src/preset/schema.c over the vendored third_party/json.h (no system JSON dependency). Field list, as implemented in src/preset/schema.c:

{
  "app": "ophis-drone", "version": 2,
  "master": 70,                     // percent 0..100 (REQUIRED)
  "bpm": 120,                       // GLOBAL tempo 1..500 (REQUIRED)
  "safety": true,                   // master safety filter (REQUIRED)
  "chain": [ 3 objects ],
  "seq":   [ 3 objects ],
  "xmod":  [ 0..16 objects ],   // ACTIVE slots only (absent slots = off)
  "delay":  { "time_l": 0.0, "time_r": 0.0,     // seconds 0..2 (REQUIRED)
              "feedback": 35, "tone": 4500.0, "mix": 30 },
  "reverb": { "size": 85, "damp": 35, "mix": 30, "width": 100 }
}
  • chain object (exactly 3, in order A, B, C): freq_hz, wave, duty, level, vel, sub (exactly 2), adsr, filter.
  • sub object: div (1..16), wave, duty (5..95), level (0..100).
  • adsr: a, d, r (seconds, 0..60) and s (percent 0..100).
  • filter: mode ("lp"|"hp"|"bp"|"br"), fc, res (0..100), env (−100..+100), poles ("12db"|"24db").
  • seq object: on, div (1..16), mode ("fwd"|"pingpong"|"oddeven"|"random"|"markov"), once (boolean; true = once, false = loop), steps (exactly 8 objects: pitch_hz, vel 0..100). No per-seq bpm — the tempo is the top-level bpm.
  • xmod entry (one per active slot): src ("off"|"b_osc"|"b_sub1"|"b_sub2"|"c_osc"|"c_sub1"|"c_sub2"|"a_osc"|"a_sub1"|"a_sub2"), tgt (0..2, default 0 = A — which chain the slot feeds), dest ("off"|"pitch"|"phase"|"amp"|"filter"|"ring"|"fm"), amount, mix (0–100: the source's audio blended into the slot's TARGET, independent of dest). The legacy stage-3 "dest": "mix" is GONE (files were rewritten).
  • chain also carries optional mixvol (0..100, default 100 — the chain's MASTER send; scales the post-ADSR/filter signal into the master sum, never modulation).
  • Wave strings: "sine"|"tri"|"saw"|"square"|"white"|"pink". Integer percent fields: master, level, vel, s, step vel, filter res and the delay/reverb percent fields.

The loader requires every listed field; unknown keys are ignored; any parse, version, range or array-length error rejects the whole file (no partial load). Array lengths are fixed: 3 chains, 2 subs, 8 steps. xmod holds 0..16 entries — the ACTIVE slots only, in ascending slot order; slots absent from the array are off (an empty array = the matrix fully off).

3. Installation

R36S / ArkOS

Build (or obtain) the deploy zip build/deploy/ophis-drone-r36s.zip (see §4). Copy its contents to the SD card so that ports/ lands at the roms/ root, giving roms/ports/Ophis-Drone.sh (launcher, must stay executable — re-chmod +x if the transfer stripped the bit) and roms/ports/ophis-drone/ophis-drone (binary). The zip also ships the factory presets (ports/ophis-drone/presets/*.json). Restart EmulationStation; "Ophis Drone" appears in the Ports menu. The launcher changes into its own directory and execs the binary. No WiFi is assumed — transfer via SD card or USB OTG. Presets are written to presets/ beside the executable on the device. Presets saved under the old $HOME/ophis-drone/presets location remain reachable via the LOAD navigator's .. traversal. Acceptance questions (video driver, audio device, buttons, preset persistence) are in CHECKLIST_R36S.md.

Desktop

Run the prebuilt binary build/desktop/ophis-drone, or build from source with make (§4). ALSA is the mandatory audio backend.

4. Building

Requirements

Desktop: gcc, make, SDL2 and ALSA development packages (pkg-config must find sdl2 and alsa; measured at M0: SDL 2.32.10, alsa 1.2.15.3), plus zip is not needed for desktop. Handheld: the aarch64-linux-gnu-gcc cross toolchain plus the arm64 SDL2/ALSA libraries and headers installed via multiarch (libsdl2-dev:arm64, libasound2-dev:arm64 under /usr/lib/aarch64-linux-gnu), and zip for the deploy archive.

Make targets

TargetOutput
make (default all)build/desktop/ophis-drone — native desktop build, -DTARGET_DESKTOP
make testbuilds and runs all 16 unit test binaries under build/tests/, prints TOTAL: N/M passed (all DSP/seq/preset tests are SDL-free; only test_engine links ALSA, on device "null")

The GLIBC ≤ 2.28 gate

ArkOS userspace derives from Ubuntu 19.10 (glibc 2.28). The handheld build links fully dynamically against the arm64 SDL2/ALSA but pins the symbols a modern host toolchain would bind too new: src/compat/glibc_symver.c provides .symver aliases for pow, log2 (@GLIBC_2.29→2.17) and pthread_create, pthread_join (@GLIBC_2.34→2.17), redirected with -Wl,--wrap; src/compat/crt0.s replaces the toolchain start file (-nostartfiles) so __libc_start_main is required at @GLIBC_2.17. tools/handheld_gate.sh, run automatically at the end of make handheld, machine-checks the result: the binary must be an aarch64 ELF and readelf -V must show no required glibc version above GLIBC_2.28. Measured output (BUILD_NOTES.md): max required version GLIBC_2.17. Details in BUILD_NOTES.md.

5. On-device verification

On-device behavior (Ports menu visibility, launch, video driver, audio, button mapping, preset save/load, stability) is manual and covered by the question checklist in CHECKLIST_R36S.md; it is not machine-verified. The machine-verified part is the host gate in tools/handheld_gate.sh and the desktop zero-xrun test (make test, test_engine).
